| 等级 | 风险 | 失败后果 | 测试策略 |

| P1 | Web/App 交互不同步 | 页面可见但命令失败或状态错误 | 唯一前端契约、浏览器快测、原生 IPC E2E、错误态注入 |
| P2 | 大资料库性能与内存 | UI 卡顿、任务不可取消、磁盘膨胀 | 10k/100k/1M 分层基准、p50/p95、RSS、索引体积和取消响应 |

## 5. 测试数据与环境

### 5.1 可复现 fixture

1. `tiny-smoke`：当前四文件 E2E 库，用于每次 PR。
2. `unicode-search`：中英文、emoji、NFC/NFD、大小写、1–2 字查询、无扩展名和误导扩展名。
3. `operation-safety`：同名、只改大小写、硬链接、符号链接、执行中修改、目标并发创建、部分完成。
4. `permission-events`：不可读目录、只读文件、监听事件风暴、休眠前后变化。
5. `external-volume`：APFS 与 exFAT；具备条件时增加 SMB/NAS，覆盖跨卷复制发布和拔盘。
6. `scale-10k/100k/1m`：固定随机种子生成目录、大小和内容分布；生成器与结果摘要纳入版本控制，文件本身不入库。
7. `similarity-labeled`：真重复、近重复、相关但不可合并、不相关四类；训练/验证按来源隔离，禁止同源泄漏。
8. `migration-corpus`：每个历史 schema 的脱敏数据库、未来版本库、截断 WAL、损坏索引和旧设置。

所有写文件测试只能操作隔离临时目录；执行前记录路径，结束后验证目录边界。禁止把个人资料库作为自动化 fixture。

## 6. 算法与性能验收指标

已确定的算法门：

- 精确重复危险误报为 0；任何内容不一致都不得进入精确重复组。
- 相似候选只读；真实验证集 Precision@10 ≥ 0.90。
- 若以后引入 ANN，Recall@10 相对精确基线 ≥ 0.95。
- 报告 TP/FP/TN/FN、precision、recall、F1、PR-AUC 和危险误报率；训练集与验证集分开。

性能报告必须同时记录机器、系统、构建模式、fixture 版本、冷/热缓存、样本数、p50/p95、峰值 RSS 和数据库/索引体积。现有 10k/100k MIH Criterion 与 1M 一次性结果只证明候选算法可运行，不代表整套应用性能。

下列预算先作为试运行门，在首轮真实 100k 基线后冻结或调整：

| 场景 | 初始预算 |
| --- | --- |
| 分析运行时 jobs/列表轮询 | p95 < 500 ms（既有修复门） |
| 100k 热搜索 | p95 < 200 ms |
| 任务暂停/取消可见反馈 | p95 < 1 s |
| 无变化重扫扩展性 | 100k 耗时不超过 10k 耗时的 20 倍 |
| UI 主线程长任务 | 单次不超过 50 ms；文件 I/O 不在命令主线程 |

预算未通过时必须保存原始结果并分析 CPU、I/O、SQLite 等待、解码和内存分配占比，不能只给总耗时。

## 7. UI、交互与可访问性验收

- 1180×760 和 900×620 必测；内容可滚动，关闭入口、主操作和任务状态不可遮挡。
- 主页面、设置、智能文件夹、清理建议、重复/相似、历史、计划和任务中心逐一检查正常、空、加载、失败状态。
- 全键盘路径：Tab/Shift+Tab、方向键、Enter、Space、Escape；焦点始终可见且弹窗关闭后返回触发点。
- 正文与说明文字对比度 ≥ 4.5:1，控件与焦点环 ≥ 3:1；中文标题无负字距。
- 应用设置与系统 `prefers-reduced-motion` 都能关闭非必要动画；同步回退不影响功能。
- 原生窗口截图作为证据，但截图不能替代点击、键盘、控制台和后端结果断言。
- 后续引入稳定截图差异测试时，字体和系统版本必须固定；差异结果由人工确认，不直接自动覆盖基线。

## 8. 故障注入与恢复矩阵

每个写操作至少在以下持久化节点强制终止一次：计划保存前、意图日志后、目标发布后、索引更新前、完成状态前。重启后分别验证磁盘、`files`、`operation_items`、路径历史和用户可见状态是否收敛。

必测故障包括：

- 源文件消失或内容/身份改变；
- 目标被并发创建、权限改变、磁盘空间不足；
- 跨卷发布校验失败或外置盘拔出；
- SQLite busy、WAL 残留、进程强杀和租约过期；
- 符号链接替换目录、授权根逃逸和路径规范化等价冲突；
- watcher 丢事件/事件风暴、休眠唤醒和资料库离线；
- 算法读取过程中修改文件、缓存损坏和算法版本升级。

P0 判定标准：不得覆盖既有目标，不得删除无法验证的内容；无法自动判定时进入 `RecoveryNeeded`，保留持久证据和明确人工出口。

## 10. 报告、缺陷与退出条件

每次测试运行保留：提交号、环境、命令、结果、耗时、失败日志、数据库/任务摘要和必要截图。缺陷至少包含可复现 fixture、预期/实际结果、风险等级、是否涉及真实文件写入以及恢复方式。

候选版本只有满足以下条件才可发布：

1. P0/P1 自动化与真机矩阵全部通过，无未解释的数据分叉。
2. 所有写操作的正常、冲突、取消、强退和撤销路径有证据。
3. 算法达到正式阈值；未达到的能力继续只读或实验开关关闭。
4. 100k 端到端预算通过，1M 结果和已知限制已记录。
5. macOS 签名、公证、安装、升级/回滚通过；Windows 发布时满足对应门。
6. 900×620 与标准窗口完成真实视觉、键盘和减少动态效果复核。
7. 文档中的完成状态、测试数量、限制和实际代码一致。
