# 归序文档中心

> 最近整理：2026-08-03

本目录按“当前状态 → 产品与架构 → 测试证据 → 专项方案 → 历史审计”组织。阅读旧审计或实施前诊断时，不应把其中的问题清单直接当作当前缺陷。

## 首要入口

| 文档 | 作用 | 更新时机 |
| --- | --- | --- |
| [开发进度](./DEVELOPMENT_STATUS.md) | 当前版本、里程碑、最新修复、验证基线、阻塞项与下一步 | 每个有效增量后 |
| [整体方案](./MASTER_PLAN.md) | 产品边界、架构、运行流程、里程碑定义和完成标准 | 架构或范围变化时 |
| [测试与分析方案](./TEST_STRATEGY_2026.md) | 测试分层、fixture、故障注入、性能预算和发布退出条件 | 测试门或风险变化时 |
| [交叉验证矩阵](./CROSS_VALIDATION_2026.md) | 代码、自动化、Web 和真实 App 证据 | 新增验证证据后 |

判断“现在做到哪里”以《开发进度》为准；判断“为什么这样设计”看《整体方案》；判断“是否已经证明可发布”看《测试与分析方案》和《交叉验证矩阵》。状态冲突时，按上述顺序回查并修正文档，不能选择更乐观的表述。

## 状态术语

| 术语 | 含义 |
| --- | --- |
| 完成 | 功能、自动化和目标平台实际交互均达到当前验收门 |
| 核心完成 | 主链路已实现并有基础测试，但仍缺真实跨卷、故障、规模或发布验证 |
| 进行中 | 已有可运行增量，仍有明确实现或准确率门未完成 |
| 待开始 | 尚未进入主线实现，不应出现在当前可用能力中 |

## 文档质量门

`node tools/verify_docs.mjs` 检查本地 Markdown 链接、必需入口和当前测试基线。它只验证结构一致性；完成状态仍必须由测试和真实 App 证据支持。
