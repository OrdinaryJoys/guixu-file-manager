审计对象：`/Volumes/FX-MD87/ai-file-manager`

审计原则：旧目录只读；所有构建产物写入临时目录；先证明当前行为，再决定保留、适配、重写或废弃。旧目录不是 Git 仓库，因此本目录中的清单、构建结果和矩阵构成迁移基线。

## 当前结论

- macOS 旧源码可用当前 Xcode 做无签名 Debug 干净构建。
- Windows 源码存在主流的原生文件夹选择器，但“整理”导航仍指向仪表盘占位页。
- macOS 整理、重命名和废纸篓操作直接修改磁盘；撤销日志只在内存中，不能作为可靠恢复机制。
- Windows 重复清理调用 `File.Delete` 永久删除且吞掉错误，禁止直接迁移。
- `docs/ARCHITECTURE.md` 描述的 Rust FFI、Qdrant、云端 Claude/GPT、Finder Extension 和 Shell Extension，在实际源码树中均不存在。
- 旧项目没有可执行的 Swift/C# 测试套件；`Package.swift` 虽声明测试 target，但未找到对应测试源码。
- 第一批安全迁移已完成：资料库全量文件数、总大小和最近修改时间由新存储层只读统计并展示；未复制旧项目磁盘写入或算法代码。
- 第二批核心闭环已完成：选择式整理计划、执行前全量预检、持久操作日志、安全移动、启动恢复审计、历史与撤销已经连通；精确重复检测只读展示，不提供永久删除入口。
- 旧版清理建议已按新边界重写：仅分析索引元数据并解释大文件、长期未修改、临时文件和陈旧下载，不自动删除或移动。

## 迁移门禁

任何旧能力进入新项目必须依次通过：

1. 临时目录中的特征测试能够复现旧行为。
2. 只读扫描和分析不产生磁盘副作用。
3. 写操作先生成计划并预演，用户确认后才执行。
4. 每个已执行步骤写入持久事务日志，并能从中断点恢复或回滚。
5. 冲突、权限变化、文件消失、跨卷移动和部分失败都有明确结果。
6. UI 只调用稳定命令接口，不直接调用 `move/delete/trash`。
